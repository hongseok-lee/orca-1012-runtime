# P1-24 — 실제 저사용 기반 자동 축소·rollback

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 3.
선행: [P1-13](P1-13.md), [P1-21](P1-21.md)~[P1-23](P1-23.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §10.8.6·§10.8.8. [공통 계약](COMMON.md)의 정확한 초기 정책값을 적용한다.

## 목적과 수정 경계

충분한 실제 저사용 증거가 있을 때 작업을 방해하지 않는 경계에서 자원을 줄인다. 수정 경계는 관측 창·DOWNSIZE operation·profile 전이·안정화/rollback과 화면 projection이다. Phase 1 필수 범위이며 Snapshot을 선행으로 하지 않는다.

## 판단 계약

1. 같은 workload profile의 최근 24h 안 실제 활동 60분, peak≤50% admitted request를 요구한다. 초기 sampling 15초·coverage≥95%·공백>60초인 창 제외를 적용한다.
2. idle/sleep/Pod 부재/metrics 누락을 0 사용량으로 세지 않는다. 낮은 CPU·오래된 누적 peak·과거 burst 여유를 메모리 축소 근거로 대체하지 않는다.
3. `target=round_up_profile_step(max(0.75×R,1.30×P,B))`, minimum≤target<R을 적용한다. 256Mi 이상 64Mi, 미만 1Mi 단위와 정확한 minimum 끝점을 포함하며 512Mi 절감 하한을 두지 않는다.
4. OOM 후 24h 보호, 축소 간 60분+새 관측 창을 지킨다. profile/작업/동시성 변경 또는 오래된 창은 재사용하지 않는다.

## 적용·실패 계약

- 목표 profile·이전 정상 크기·관측 창·operation을 영속화하고 turn/tool/background writer가 없는 안전한 다음 sleep/wake 경계에서 적용한다. pending 입력은 축소보다 우선한다.
- 실제 적용 직전 intent·새 입력·관측 freshness를 다시 확인하고 old writer 차단→새 profile→실제 admitted 자원→동일 Session binding을 수행한다.
- 축소 전 예산에 직전 정상 크기로 한 번 복귀할 여유를 포함한다. 안정화 전 memory OOM/eviction에는 operation당 별도 1회 rollback을 허용하되 총예산·상한·single writer는 지킨다.
- 직전 크기보다 추가 증설이 필요하면 그 추가분은 일반 growth 예산을 쓴다. rollback 반복은 금지하며 capacity 부족은 입력 보존 RESOURCE_WAIT다.
- 대표 작업 완료+실제 활동 60분 안정화 전 실패를 축소 실패로 기록하고 같은 workload profile의 추가 축소를 24h 금지한다. 재시도에는 새 저사용 증거가 필요하다.

## 완료·검증 기준

V1-12에서 유효/결측 관측, 25% 단계와 minimum 도달, 새 입력/close/OOM 경합, 실제 admission 반등, rollback 1회·24h 보호·Active 교체를 검증한다. 실행 중 작업을 비용 절감 목적으로 중단하지 않고 실제 자원 적용 전 절감 완료로 표시하지 않는다. 물리 Node/청구액이 같은 비율로 줄었다고 추정하지 않는다.

## 산출물·연계

관측/정책·operation/rollback 증거를 제출한다. Phase 2 복원 RAM과 축소 호환성은 P2-08이 추가하며 Phase 1의 안전한 cold 경계를 막지 않는다.
