# O-01 — NFS 백업 검증·기존 GKE 삭제 완료 기록

상태: 기존 실행 완료 · 구분: 운영 선행 작업의 보존 명세.
실행 근거: 클러스터 삭제 기록 (비공개 운영 기록), 접근·초기 백업 기록 (비공개 운영 기록). [공통 계약](COMMON.md)을 적용한다.

## 목적과 완료 범위

NFS writer를 정지하고 현재 관리 VM에 마지막 데이터를 검증 가능한 형태로 보존한 뒤 기존 클러스터를 삭제했다. 이 파일은 완료된 작업의 계약·증거 위치를 기록하며 삭제를 다시 실행하는 지시가 아니다.

## 실행 대상·보존 경계

- 삭제 대상: `<gcp-project> / asia-northeast3 / <historical-cluster>`.
- 보존 대상: 관리 VM `<protected-admin-vm>`, 데이터 디스크 `<protected-admin-disk>`, `<protected-operator-backup>`의 백업, 계정 자격·공유 인프라·독립 자원·동결 템플릿/원본 이력.
- VM의 deletionProtection과 데이터 디스크 autoDelete=false를 확인했다. 클러스터 삭제 후 남은 디스크 2개는 inventory만 기록했고 개별 삭제하지 않았다.

## 계속 지킬 보존 계약

archive만 따로 보존하지 않는다. `source-metadata.jsonl`, `restore_metadata.py`, `source-sha256.json`, manifest, SHA256SUMS, RESTORE.md와 관련 증거를 포함한 디렉터리 전체가 복원 묶음이다. 나노초 timestamp 복원에는 sidecar와 복원 도구가 필요하다. 기존 이전 백업도 별도로 보존한다.

## 검증 한계

ACL/xattr의 존재·보존은 미확인이다. runtime socket은 재생성 대상이며 ctime/birthtime 이식 보장을 하지 않는다. 파일/metadata/SQLite 검증은 provider-native resume·메모리/PID·미완료 외부 효과의 연속성을 증명하지 않는다. RV-09의 한계는 제품 복구 시험과 별개로 유지한다.

## 후속 연결
