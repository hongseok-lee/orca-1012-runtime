# P1-17 — structured Session 생성·Chat 공개 RPC adapter

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 3.
선행: [P1-04](P1-04.md)~[P1-08](P1-08.md), [P1-11](P1-11.md), [P1-16](P1-16.md). 지원 활성화 gate: [G-02](G-02.md)·[G-05](G-05.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §7–7.1.1. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

§7의 structured `agentSession` RPC 전체를 공통 영속 core에 연결한다. 수정 경계는 기존 strict schema/handler와 mutation result/journal adapter다. `createSupport/create`도 명시적으로 이 작업의 소유다.

## 공개 계약

| 메서드 | 필수 동작 |
|---|---|
| `createSupport` | provider·설치 앱 capability·서버 adapter 준비를 판정한다. Pod 유무와 지원 여부를 혼동하지 않는다. |
| `create` | 기존 envelope·worktree/agent/resumeFrom으로 Session+journal+Tab을 영속 생성한다. Pod 0 생성이 가능하고 실제 provider handle은 후속 binding이다. |
| `send` | clientOperationId와 검증된 fingerprint/fence를 사용해 본문·첨부 접수 후 기존 mutation result와 pending submission을 반환한다. Pod 준비까지 RPC를 붙잡지 않는다. |
| `history/subscribe` | 영속 journal epoch/sequence의 snapshot/replay를 제공한다. provider event는 commit 후 publish한다. |
| `cancel` | 기존 turnId로 정확한 취소 대상을 고정한다. `cancelled`는 기존 계약에 맞는 확정 결과에만 사용한다. |
| `respondToQuestion/respondToApproval` | operation ID·itemId·expectedRevision CAS와 현재 Session/turn/질문 유효성을 확인한다. 옛 답변을 다음 질문에 재사용하지 않는다. |
| `hold/release` | connection-scoped observer를 관리한다. 화면 닫힘을 작업 취소로, hold를 Compute 유지 사유로 취급하지 않는다. |
| `setOption/conversationCommand/rewind/handoff` | 입력과 같은 순서/직렬화 경계를 사용한다. queued와 실제 완료를 구분하고 관련 Snapshot 무효화 계약을 보존한다. |

## 응답과 capability

- 기존 envelope, `ok/replayed/fence/cursor/value`, clientMessageId/submission 및 strict validator를 유지한다.
- 공개 dispatchState는 pending/accepted/rejected/unknown만 사용한다. pending은 영속 접수, accepted는 provider 수락 증거, unknown은 실행 효과 불명이다. 준비 대기를 unknown으로 표시하지 않는다.
- structured·Claude structured·pending-send capability를 각각 실제 협상한다. 가짜 provider/thread/turn ID나 미검증 fallback을 도입하지 않는다.
- turnId 없는 iPhone pending Stop의 비활성을 인정한다. 기존 논리 turnId 경로를 쓰려면 발급부터 앱 수신·cancel까지 G-02로 증명해야 한다.

## 완료·검증 기준

V1-01/04/05/06에서 createSupport→Pod 0 create→후속 binding→send/history, 같은 key retry, 질문 revision 경합, pending/실행 중 Stop, 빠른 Stop 두 번+새 입력을 실제 지원 조합별로 검증한다. 새 공개 RPC나 앱 수정 없이 기존 schema를 통과하고 미지원 조합은 정직하게 남긴다.

## 산출물·연계

전체 structured handler 대응표와 실제 wire/capability 증거를 제출한다. P1-20의 journal/projection, P1-14의 공개 HA 통합과 합류한다. nativeChat는 P1-20, legacy/raw Terminal은 P1-18/19, clipboard 내구성은 P1-04의 계약을 사용한다.
