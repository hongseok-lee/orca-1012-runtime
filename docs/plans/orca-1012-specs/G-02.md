# G-02 — 설치 앱 capability·Stop 대상·Browser 실증

상태: 증거 미확보 · 구분: 공개 기능 활성화 gate.
연계: [P1-17](P1-17.md)·[P1-18](P1-18.md)·[P1-19](P1-19.md)·[P1-20](P1-20.md)·[P1-27](P1-27.md)·[P1-30](P1-30.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §7.1.1·§13.1·§16. [공통 계약](COMMON.md)을 적용한다.

## 목적과 범위

실제 설치된 iPhone/Mac 앱의 structured Chat, Claude 지원, pending-send, pending Stop, legacy 입력, Browser 경로를 조합별로 확인한다. 서버 flag나 소스에 메서드가 있다는 사실만으로 설치 앱 지원을 광고하지 않는다.

## 확보할 계약·자료

1. 앱 버전·연결 경로·provider·Pod 유무별 capability 행렬을 기록한다. structured와 legacy를 분리한다.
2. `turnId` 발급→journal/activity→앱 수신→Stop payload→서버의 Message/attempt/epoch 매핑을 실제 ID로 추적한다. 가짜 turnId로 시험을 통과시키지 않는다.
3. turnId 없는 iPhone structured pending Stop은 비활성을 그대로 인정한다. Mac Stop과 legacy ESC의 의미도 관측 없이 추정하지 않는다.
4. 기존 `browser.tabCreate`와 browser-screencast 협상, 중앙 Browser 실행/streaming, 인증 연결을 실제 기기에서 확인한다.
5. 미지원 조합은 기존 공개 응답/화면 의미 안에서 표시하며 앱 수정이나 새 RPC를 요구하는 우회책을 추가하지 않는다.

## 완료·검증 기준

- Pod 0 pending, active turn, settled turn, 빠른 Stop 두 번+새 입력의 실제 대상 연결을 검증한다. 이미 종료되거나 다른 attempt의 turn을 잘못 취소하지 않는다.
- 기기별 pending 입력 수락·재연결·취소 결과와 지원/미지원 사유가 증거로 남는다.
- Agent Pod 0에서도 두 기기의 Browser Tab에 중앙 운영 화면이 열리고 인증이 이어진다.
- V1-01/04/05/14와 연결한 행렬에서 미검증 행을 합격 처리하지 않는다. 실제 기기를 사용할 수 없는 경우 그 행은 미검증으로 남긴다.

## 산출물

기기/provider/capability 행렬, 실제 RPC·ID 연계 증거와 Browser 결과를 제출한다. 해당 증거를 갖춘 기능만 활성화하며 이 gate 대기만으로 공통 입력 core 작성을 중단하지 않는다.
