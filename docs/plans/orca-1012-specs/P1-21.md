# P1-21 — 메모리·종료 증거 수집·incident dedup

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 3.
선행: [P1-03](P1-03.md)·[P1-09](P1-09.md)·[P1-12](P1-12.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §10.8.1–2. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

실제 메모리 부족과 다른 종료를 구분하고 같은 종료로 중복 증설하지 않게 한다. 수정 경계는 K8s/gateway/cgroup 증거 수집, incident 정규화·분류와 영속 audit다.

## 분류 계약

| 분류 | 판정·연결할 행동 |
|---|---|
| ISOLATED_NODE_MEMORY_EXHAUSTION | 1 Runtime Unit/Node·limit 없음이 확인된 memory eviction/node OOM은 기본 자동 증설 대상이다. cgroup 파일 부재만으로 배제하지 않는다. |
| CONTAINER_LIMIT_OOM | 해당 container/epoch의 limit OOM 증거를 연결한다. 기본 모드에서는 limit 주입 drift를 확인한다. |
| SHARED_NODE_MEMORY_PRESSURE | 다른 사용자 workload 동거·격리 이탈을 기록하고 배치 원인과 구분한다. |
| PROCESS_HEAP_LIMIT | runtime heap 한도를 진단한다. Pod RAM 증가로 해결된다고 가정하지 않는다. |
| CHILD_CGROUP_OOM | 신뢰된 자식 종료 증거와 작업 영향을 확인한다. 살아 있는 다른 작업을 즉시 삭제하지 않고 quiesce/fence 경로로 연결한다. |
| UNKNOWN_MEMORY_FAILURE | exit137 단독 등은 유한한 증거 수집 후 분류/대기 사유로 남긴다. |
| OTHER_TERMINATION | Spot·수동 SIGKILL·probe·disk pressure는 원인별 복구로 보내고 RAM을 자동 증설하지 않는다. |

## 수집·중복 방지

- Pod UID·container identity·restart/incarnation·종료 시각 또는 counter 증가를 정규화한 evidence key로 dedup한다. eviction/OOMKilled가 같은 종료면 같은 incident/episode로 합친다.
- 실제 admitted requests/limits, Node 배치, K8s reason/message, 접근 가능한 신뢰된 counters/peak와 출처를 저장한다. 다음 restart가 lastState를 덮기 전에 보존한다.
- 주기적 표본의 마지막 값이 낮다고 OOM을 부정하지 않는다. 모델이 출력한 “OOM”이나 임의 stderr 문자열만으로 증설 권한을 주지 않는다.
- 증거 수집 deadline을 넘기면 RESOURCE_WAIT/BLOCKED 원인을 남긴다. 근거 없는 무한 조사·교체를 하지 않으며 제한적 교체도 기존 replacement 예산을 사용한다.

## 완료·검증 기준

V1-11에서 각 분류, gVisor cgroup 미노출과 명시적 memory eviction, 짧은 spike, 같은 lastState 반복 watch를 검증한다. 같은 종료에서 incident/증설 의도가 한 번만 생성되고 근거·불명·관측 gap이 보존된다. 플랫폼 DaemonSet/balloon과 다른 사용자 Runtime Unit 동거를 구분한다.

## 산출물·연계

분류기·evidence schema·dedup 결과를 제출한다. G-03의 실제 격리/admission 증거와 P1-22/23의 자원 정책에 연결하며 incident 생성 자체를 증설 완료로 표시하지 않는다.
