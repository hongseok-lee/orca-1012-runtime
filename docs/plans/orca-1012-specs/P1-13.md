# P1-13 — 영속 lifecycle·deadline·idle/sleep·wake 병합

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 2.
선행: [P1-06](P1-06.md)~[P1-12](P1-12.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §9.1–3·§12. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

입력·실제 실행·UI 상태를 구분하는 중앙 reconciliation을 만든다. 수정 경계는 Runtime Unit/member 상태 전이, operation/deadline, watch+LIST 복구, idle/sleep/wake 정책과 runtime 명령 연계다.

## 구현 계약

1. desired·observed·UI projection을 분리하고 PG revision/intent/operation을 정본으로 삼는다. watch 연결과 메모리 timer는 재구축 가능해야 한다.
2. K8s watch 단절 후 LIST와 영속 deadline으로 수렴한다. 결정적 외부 리소스 이름과 실제 create 결과 조회로 응답 유실 뒤 중복 Pod를 막는다.
3. 같은 compatible RUNNING/wake 상태의 입력은 기존 wake를 공유한다. 읽기·hold·protocol traffic을 업무 활동으로 세거나 매 입력마다 새 lifecycle intent를 만들지 않는다.
4. sleep과 새 입력/close를 같은 intent/revision 경계에서 직렬화한다. 새로운 작업이 생긴 상태를 잠든 것으로 확정하거나 닫힌 Tab을 재등록하지 않는다.
5. Runtime Unit의 여러 member에 걸친 turn/tool/background writer를 함께 확인한다. 한 Session의 idle만으로 다른 member 작업을 종료하지 않는다.
6. operation의 단계·실제 명령 결과·deadline/retry는 PG에 남긴다. 이전 writer 차단 뒤 새 attempt를 허용하며 불명 상태를 정상 종료로 바꾸지 않는다.

## 완료·검증 기준

- V1-08: sleep/입력/close 동시 경합과 다중 member 작업에서 접수 입력 유실·중복 실행·닫힌 Tab 부활이 없다.
- watch 단절·LIST 복구·controller crash·create ACK 유실 뒤 같은 desired state로 수렴한다.
- 조회/hold/Terminal 제어 traffic만으로 wake하거나 idle 기한을 늘리지 않는다.
- operation 소유권·실제 writer 증거가 불명일 때 실패 상태와 입력을 보존하고 안전 조건 전 새 실행을 열지 않는다.

## 산출물·연계

상태 전이·deadline·reconcile 구현과 경합 증거를 제출한다. 6시간 관측 장애는 P1-15, 자원 정책은 P1-21~24, HA 인수는 P1-14가 이 core를 사용한다. G-01 뒤 root가 실제 파일별 위임 범위를 확정한다.

## 병렬 납품 경계

intent/operation·상태 projection·reconcile 입출력 계약을 먼저 확정하고, 상태/기한 모듈과 실제 runtime 연결을 나누어 납품한다. 이를 사용해 P1-16 Catalog, P1-14 제어기, 자원 명령 코드를 분리 작성할 수 있다. 공용 controller 상태 전이는 한 소유자가 반영하며, 전체 완료는 P1-06~12와 실제 sleep/wake/close/fencing 증거 합류 후다.
