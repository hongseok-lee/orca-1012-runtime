# P1-19 — Logical Terminal·raw PTY·binary stream 호환

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 3.
선행: [P1-09](P1-09.md)·[P1-11](P1-11.md)·[P1-13](P1-13.md)·[P1-16](P1-16.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §7·§7.2·§13. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

논리 Terminal의 연결/기록과 실제 PTY incarnation을 분리하고 기존 binary client와 호환한다. 수정 경계는 terminal list/resolve/subscribe/read, stream·input floor, PTY bind/raw send와 viewport/buffer handler다.

## 구현 계약

1. stable handle·pane 해석·input floor·`mobileInputLeaseOnly` stream을 Pod 0에서도 유지한다. Pod 부재만으로 논리 stream에 end를 보내지 않는다.
2. mobile 호환 `connected/writable` projection과 실제 process liveness를 분리한다. 내부 idle controller는 UI projection을 실행 증거로 사용하지 않는다.
3. 기존 binary handshake/frame/sequence/ACK와 ANSI buffer snapshot/replay를 실제 decoder가 이해하도록 구현한다. 빈 JSON subscribed 응답만으로 준비 완료를 표시하지 않는다.
4. raw shell/TUI bytes는 현재 PTY incarnation에만 전달한다. 준비 전 지원 불가 입력은 false/error로 반환하고 불명 전달을 새 Pod로 자동 replay하지 않는다.
5. terminal.read는 보존 출력과 logical stream cursor를 제공한다. ANSI 화면 snapshot과 프로세스 memory Snapshot을 구분한다.
6. viewport/autoRestoreFit은 저장 후 실행 연결 때 적용한다. focus·resize·query-reply를 wake/업무 활동으로 세지 않는다.
7. clearBuffer는 표시용 scrollback만 정리한다. Session journal·접수 Message·draft clear와 혼동하지 않는다.

## 완료·검증 기준

- V1-04/13: 실제 binary decoder/client에서 연결·ACK·재연결·buffer replay·viewport를 검증한다.
- Pod 0 input-floor stream과 새 PTY binding에서 stable handle이 유지된다.
- raw write 응답 유실/attempt 교체 뒤 다음 PTY로 바이트가 자동 replay되지 않는다.
- 여러 클라이언트의 조회/Chat 접수와 raw input lease가 독립적으로 동작한다.
- 단순 Terminal 제어 traffic으로 Agent wake/idle 연장이 발생하지 않는다.

## 산출물·연계

Terminal/stream 계약·실제 decoder 결과·incarnation 경계 증거를 제출한다. managed Chat 분류는 P1-18, semantic 출력/history는 P1-20과 연결한다.
