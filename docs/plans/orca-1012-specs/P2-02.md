# P2-02 — 디렉터리 변경 기록·storage seal

상태: 구현 미착수 · 단계: Phase 2 / 착수 묶음 6.
선행: [P1-10](P1-10.md)·[P2-01](P2-01.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §10.3.1. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

Snapshot과 실제 영속 파일 사이의 변경 여부를 canonical write domain 단위로 판정한다. 수정 경계는 NFS 서버 측 변경 기록/검증 경로, seal repository, restore 직전 비교다.

## 봉인 계약

1. 대상은 Snapshot에 포함된 Session의 실제 홈/checkout 범위다. 같은 export의 다른 Agent 디렉터리 변경까지 한꺼번에 무효화하지 않는다.
2. `sealed_at`, `source_stopped_at`, `storage_epoch`, `directory_mutation_seq`, `latest_file_mtime`, `watch_coverage`를 영속 저장한다.
3. 단일 RW 소유권·봉인 이후 writer 없음·서버 변경 순번을 주 근거로 사용한다. 복원 직전 서버 원본 filesystem 또는 검증된 재검증 경로를 조회하고 reader의 cached stat에만 의존하지 않는다.
4. 생성·삭제·rename·truncate·동일 크기 덮어쓰기·mtime 보존 변경을 추적한다. 디렉터리 mtime 하나만으로 미변경을 증명하지 않는다.
5. 공용 credential/cache가 복원 프로세스에 영향을 주면 별도 버전/재로딩 또는 관련 무효화 조건을 연결한다.

## 판정 계약

| 관측 | 결과 |
|---|---|
| mutation seq 또는 storage epoch 차이 | 시차와 관계없이 cold fallback |
| 최신 파일 mtime > sealed_at+2초 | FILES_NEWER_THAN_SNAPSHOT으로 cold fallback |
| 시차 2초 이내 | 단독 허가 불가; seq·writer 정지·coverage를 함께 확인 |
| watch 재시작/overflow/기록 gap/시계 불명 | seal UNKNOWN, cold fallback |
| 오랜 휴면이나 실제 변경 없음 | 경과 시간만으로 Snapshot 폐기하지 않음 |

## 완료·검증 기준

각 변경 종류, 서버 watch gap·cached metadata·시계 불명, 다른 Agent 변경, 장기 휴면을 실제 NFS에서 검증한다. 2초는 변경 허용 창이 아니며 seq 불일치가 있으면 짧은 시차에도 거절한다. 판정과 실제 파일 변경 증거가 연결돼야 한다.

## 산출물·연계

서버 변경 기록·seal 모델/판정·NFS 증거를 제출한다. P2-03/04/05가 사용하며 cold fallback도 기존 writer fencing을 생략하지 않는다.
