# P1-12 — PG 영속 사건 큐·producer ACK·consumer 재시도

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 2.
선행: [P1-02](P1-02.md)·[P1-03](P1-03.md)·[P1-09](P1-09.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §9.2.1·§15.1. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

runtime 사건의 전송 내구성과 업무 처리 재시도를 분리해 보존한다. 수정 경계는 producer 영속 outbox/spool, PG enqueue/ACK, consumer head·시도 이력과 terminal commit이다.

## 구현 계약

1. producer/incarnation/sequence와 canonical event ID로 중복을 막는다. producer는 영속 outbox를 갖고 PG의 gap-free enqueue ACK를 기준으로 전송 상태를 관리한다.
2. ACK는 연속 prefix가 PG에 저장됐다는 뜻이다. consumer projection 처리 완료와 혼동하지 않는다. seq 11이 먼저 도착해도 누락된 10을 넘겨 연속 ACK하지 않는다.
3. Agent/producer별 head 순서를 지킨다. 미수신 gap 또는 terminal 처리되지 않은 실패 head를 건너뛰지 않는다.
4. consumer는 최초 1회+재시도 5회, 총 6회를 상한으로 한다. 시작/결과/오류·다음 retry 시각·횟수를 PG에 보존하고 crash/Active 교체로 초기화하지 않는다.
5. 성공은 projection/outbox/DONE을 원자 commit한다. 소진 실패는 원 payload·원인·시도 이력·FAILED·Session context/revision·알림을 원자 commit한다.
6. FAILED의 성공 `processed_at`을 채우지 않는다. terminal 실패가 확정된 뒤 다음 사건으로 진행한다. context는 P1-08, 알림은 P1-25와 연결한다.

## 완료·검증 기준

- V1-07: seq 11→10, 중복 전송, producer 재시작과 ACK 유실에서 gap-free 저장/ACK가 유지된다.
- 3번째 시도 뒤 crash/Active 교체를 넣어도 총 6회를 넘지 않는다.
- FAILED commit 전 crash에서 다음 사건으로 넘어가지 않고, commit 후에는 실패 기록과 context/알림을 보존한 채 진행한다.
- successful projection만 남거나 FAILED 없이 head를 넘기는 부분 transaction이 없다.

## 산출물·연계

producer/consumer 프로토콜·PG 시도 이력·재시작/소진 증거를 제출한다. P1-13/14는 이 영속 head·deadline을 인수하며 메모리 queue를 별도 정본으로 만들지 않는다.
