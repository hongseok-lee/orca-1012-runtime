# C-01 — 조건부 과거 PostgreSQL backup/PITR 복원 자동화

상태: 조건부·현재 필수 구현 범위 아님.
적용 조건: 과거 백업/PITR로 DB를 되감는 자동화 기능을 명시적으로 도입하는 경우.
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §4.3·리뷰 R08. [공통 계약](COMMON.md)을 적용한다.

## 목적과 구분

과거 DB 상태를 복원할 때 이미 외부에서 실행된 효과와 DB 기록이 어긋나는 문제를 다룬다. 일반 Spot 회수 후 동일 디스크/WAL 복구, O-01의 NFS 운영 백업, 단일 PG의 기본 백업/복원 절차와 구분한다.

## 조건이 충족될 때의 계약

1. 과거 DB 복원 후 RECOVERY_HOLD와 새로운 recovery incarnation으로 시작한다. 이전 DB가 기억하는 실행 grant를 그대로 유효하게 사용하지 않는다.
2. 이전 실행/외부 효과 권한을 차단하고 provider 이력·파일·외부 결과와 복원 DB를 먼저 대조한다.
3. 확인되지 않은 입력은 UNKNOWN으로 남겨 P1-08 복구 context에 연결한다. 증거 부재를 미실행 증명으로 취급하지 않는다.
4. 과거 DB의 pending Message나 미소비 Snapshot을 무조건 다시 실행하지 않는다. 최신 외부 사실과 소유권을 확인한 뒤 새 권한을 부여한다.
5. 영향 범위·recovery generation·대조 증거·승인된 재개 결과를 추적한다. 입력과 원 결과 이력을 삭제해 정합성을 가장하지 않는다.

## 조건부 완료·검증 기준

기능 도입 시 root가 구체 위임을 확정한다. DB 복원 시점 이후 provider 실행/파일 변경이 있는 사례, 옛 grant 복귀, 과거 pending/READY_SEALED Snapshot, 불명 외부 결과를 검증해야 한다. 대조 전 실행이 재개되지 않고 UNKNOWN이 보존되는 증거가 필요하다.

## 현재 처리

이번 명세 작성으로 이 기능을 활성화하거나 Phase 1 HA의 필수 gate로 추가하지 않는다. 과거 DB 복원 자동화가 도입되지 않는 동안 조건부 상태를 유지한다.
