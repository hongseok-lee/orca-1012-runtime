# P2-10 — 선택적 mid-turn FROZEN_TURN 이동

상태: 선택 기능·구현 미착수 · 단계: Phase 2 후속, 별도 활성화 판정.
선행: [P2-09](P2-09.md) 통과와 root의 기능별 적용 범위 판정.
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §10.3·§10.6·§10.8.9·§16. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

실행 중인 turn을 이동해야 하는 검증된 상황에서만 FROZEN_TURN capture/restore를 지원한다. 수정 경계는 capture mode·진행 효과 증거·process freeze/restore와 연결 재수립이다. 정상 quiescent 경로와 구분한다.

## 활성화 전 계약

1. active provider 요청, 도구/자식/background 작업, in-flight I/O, 파일 flush/변경과 외부 연결의 상태를 기록한다.
2. 전체 process tree·writer가 이동 중 실제로 정지하고 새 ticket 이전 효과가 차단됨을 P2-01 gate로 확인한다.
3. 아직 끝나지 않은 turn이 있으면 QUIESCENT로 표시하지 않는다. manifest의 capture mode와 uncertain effects를 실제 상태에 맞춘다.
4. 원격 요청/도구의 결과 증거와 재연결·재시도 계약으로 외부 효과 중복 가능성을 판정한다. 증거 부재를 미실행으로 간주하거나 exactly-once를 주장하지 않는다.
5. 최신 취소/context/질문/Tab close/member, storage seal·CONSUMED·단일 RW·예산과 cold fallback을 유지한다.
6. 검증된 provider/작업/연결 범위에서만 선택적으로 활성화한다. 모든 150% 사건에 Snapshot을 강제하지 않고 live 경로 P2-06을 유지한다.

## 완료·검증 기준

실제 Claude/Codex의 진행 turn·원격 요청·background tool·NFS 쓰기·연결 단절에서 freeze→checkpoint→restore→새 허가 순서를 검증한다. 중복 외부 효과의 불확정 구간을 보존하고 불충족 조합은 미지원으로 남긴다. 안전성을 증명하지 못한 상태를 일반 quiescent 합격으로 우회하지 않는다.

## 산출물·범위

지원 조합별 증거 계약·실제 이동/실패 결과·명시적 활성화 범위를 제출한다. 선택 기능이므로 미구현 상태만으로 Phase 1이나 P2-01~09의 합격을 막지 않는다.
