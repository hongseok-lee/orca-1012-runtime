# P2-08 — Snapshot 필요 RAM을 고려한 축소·Dashboard 연결

상태: 구현 미착수 · 단계: Phase 2 / 착수 묶음 6.
선행: [P1-24](P1-24.md)·[P1-26](P1-26.md)·[P1-27](P1-27.md), [P2-04](P2-04.md)·[P2-05](P2-05.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §10.8.8·§13.1·§14. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

Phase 1 축소 정책에 실제 Snapshot 복원 필요량을 반영하고 검증된 Phase 2 운영 기능을 화면에 연결한다. 수정 경계는 축소 하한/호환성 판정과 기존 Dashboard command/status/action 표시다.

## 구현 계약

1. 복원 직후 상주 메모리·복원 오버헤드의 검증된 필요량을 P1-24 공식의 B에 포함한다. 압축 Snapshot 파일 크기를 필요 RAM으로 사용하지 않는다.
2. 유효 Snapshot이 목표 RAM보다 크거나 축소 복원 호환성이 불명확하면 축소를 보류하고 기존 크기로 memory resume한다. 비용 최적화가 snapshot-first를 조용히 cold로 바꾸지 않는다.
3. Snapshot 자체가 무효/실패해 기존 cold fallback이 필요한 경우에만 현재 cold 시작 필요량을 만족하는 낮은 profile을 검토한다. 새로운 강제 Snapshot 무효화 정책을 만들지 않는다.
4. 기존 실제 활동 관측·25% 단계·minimum·24h 보호·별도 1회 rollback·single writer·예산을 유지한다.
5. 안전 checkpoint/restore의 durable command, Snapshot/복원 모드·현재/목표 자원·접수/실제 결과를 기존 Dashboard에 연결한다. 검증된 경로만 활성화한다.
6. 화면 열람은 wake/idle 연장이 아니며 기존 인증·replay·알림 계약을 유지한다.

## 완료·검증 기준

충분한/부족한 target RAM·불명 호환성·Snapshot 무효/실패, 새 입력/close 경합, 축소 실패 rollback을 검증한다. 기존 크기 복원 보류 사유와 실제 적용 결과가 UI/API에서 일치한다. iPhone/Mac의 기존 Browser Tab에서 검증된 명령만 제공된다.

## 산출물·연계

복원 RAM 증거·축소 판정·Dashboard 변경과 실제 명령 결과를 제출한다. 물리 메모리/청구 절감을 request 감소만으로 단정하지 않는다.
