# P1-26 — Dashboard HTTP·인증·durable command API

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 4.
선행: [P1-13](P1-13.md)·[P1-22](P1-22.md)·[P1-25](P1-25.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §13.1–2. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

중앙 운영 화면용 HTTP API를 제공한다. 수정 경계는 `/ops/v1` handler·기존 인증/CSRF 연결·영속 command admission·조회 projection이다. iPhone/Mac 공개 RPC를 추가하는 작업이 아니다.

## API 계약

| 경로 | 필수 동작 |
|---|---|
| `GET /ops/v1/runtime-units` | revision·상태·자원·관측 시각이 있는 목록 |
| `GET /ops/v1/runtime-units/:id` | Session/Tab/attempt/profile/mount/최근 사건 상세 |
| `GET /ops/v1/events?unit=&after=` | 공통 replay cursor의 사건/로그 페이지 |
| `GET /ops/v1/events/stream?unit=&after=` | 같은 cursor의 SSE·재연결·범위 밖 reset |
| `POST /ops/v1/runtime-units/:id/commands` | operationId/expectedRevision/action/params 검증 후 durable operation 저장, 202+operation ID 반환 |
| `GET /ops/v1/operations/:id` | 실제 적용·대기·실패와 원인 조회 |
| `GET /ops/v1/notifications?state=&after=` | 영속 알림·읽음/해결·대상/원인/재시도 조회 |
| `POST /ops/v1/notifications/:id/read` | operationId/expectedRevision으로 읽음 갱신; 해결 상태는 유지 |

## 제어·인증 계약

1. wake·안전 sleep·profile/자동 정책 변경·명시적 복구 재시도는 공통 lifecycle controller로 실행한다. 웹 handler가 직접 K8s patch하는 별도 제어 소유자가 되지 않는다.
2. 202는 접수이며 실제 적용 완료가 아니다. active 작업 중 변경은 대기로 표시하고 강제 중단의 대상·이유를 명확히 한다.
3. 유효 인증키 또는 그 키로 검증된 기존 인증 세션을 사용한다. 기존 cookie/CSRF 보호를 유지하고 URL/로그에 장기 키를 넣지 않는다.
4. 새로운 기기별 권한 회수·SSE 강제 종료·30초 재인가를 추가하지 않는다. 내부 operation/term/fencing 권한 검사는 유지한다.
5. Phase 2 checkpoint/restore action은 미지원으로 정확히 표시한다. UNKNOWN 전용 강제 해결/재실행 버튼은 만들지 않는다.

## 완료·검증 기준

V1-13/14에서 유효/무효 인증, 기존 CSRF, command retry/payload conflict/revision 경합, 202 이후 실제 결과, 페이지→SSE/reconnect/reset, notification 읽음/해결을 검증한다. DB 접수 실패나 writer 차단 실패를 성공으로 표시하지 않으며 Agent Pod 0에서도 중앙 API가 동작한다.

## 산출물·연계

HTTP 계약/handler·인증 연결·명령 상태와 replay 증거를 제출한다. P1-27이 실제 Browser Tab에서 사용한다.

## 병렬 납품 경계

P1-13/22/25의 명령·projection 계약에 맞춘 HTTP/auth/cursor/operation 상태 계약을 먼저 넘겨 P1-27 UI와 병렬 작성한다. 실제 자원 명령 검증은 P1-23/24 등 해당 controller 구현·결과와 합류한다. 이 조건을 모든 읽기 API의 새 전역 선행으로 확대하지 않으며, 202 응답만으로 명령 동작 시험을 완료하지 않는다.
