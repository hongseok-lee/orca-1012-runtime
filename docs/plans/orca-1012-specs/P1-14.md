# P1-14 — Orca Serve Spot 2개 Active/Standby·인수

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 3.
core 선행: [P1-09](P1-09.md)·[P1-12](P1-12.md)·[P1-13](P1-13.md).
최종 통합 완료 선행: [P1-16](P1-16.md)~[P1-20](P1-20.md) 공개 경로 합류.
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §4.2·§9.2·§12. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

PG가 사용 가능한 동안 Orca Serve의 Spot 회수를 견디며 제어권과 공개 접속을 이어간다. 수정 경계는 두 replica 배치·leader lease/term·operation 인수·공유 공개 접속 상태다.

## 구현 계약

1. 서로 다른 Spot 노드에 Serve 두 실행을 둔다. Active만 watch 처리와 lifecycle 명령을 소유하고 Standby는 PG lease 만료 뒤 DB 시간+CAS로 새 term을 얻는다.
2. 새 Active는 기존 desired/observed state, idle/retry/관측 장애 deadline, 사건 head/시도 예산, 진행 operation을 이어받는다. 서버 교체로 기한/예산을 재설정하지 않는다.
3. 이미 수락된 외부 명령의 실제 결과를 조회해 인수한다. 옛 term의 늦은 명령은 실제 수락/실행 경계에서 차단한다.
4. 정상 Agent를 서버 인수만으로 재실행하지 않는다. 논리 host 주소·기존 인증 세션·Catalog 목록·원 receipt·journal/cursor replay가 이어져야 한다.
5. PG 자체 가용성은 별도다. 단일 PG 재기동 중 접수/제어 중단 가능성을 명시하고 Serve replica 2개를 DB HA로 표시하지 않는다.

## 완료·검증 기준

- 제어기/lease/term 단위 합격은 중간 상태로 기록한다. 이 상태만으로 P1-14를 최종 완료하지 않는다.
- V1-07/09: 시도 중 Active 회수, 수락된 외부 명령 인수, 이전 term 복귀에서 소유자 중복·예산 초기화·중복 writer가 없다.
- V1-13 및 P1-16~20의 실제 공개 경로에서 Active 교체 뒤 같은 host·인증·목록·receipt 조회·구독 replay를 확인한다.
- 정상 Agent/Session/Tab identity가 유지되고 접수된 입력·commit된 출력이 사라지지 않는다.

## 산출물·병렬화

배치·lease/인수 코드와 제어기 단위/공개 RPC 통합 증거를 별도로 제출한다. 공통 계약 이후 HA와 RPC 코드는 병렬 작성 가능하다. RV-01의 보완에 따라 공개 경로 합류 전에 최종 완료를 선언하지 않는다.
