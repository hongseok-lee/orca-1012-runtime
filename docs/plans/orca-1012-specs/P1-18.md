# P1-18 — iPhone/Mac legacy draft·입력 분류 adapter

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 3.
선행: [P1-04](P1-04.md)~[P1-08](P1-08.md), [P1-16](P1-16.md). 실기기 gate: [G-02](G-02.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §7.2·§8.2. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

기기별 wire 입력을 영속 draft와 공통 intake로 변환한다. 수정 경계는 managed Chat의 `terminal.send`, 서버 검증 기기/floor 귀속, draft repository와 의미 분류기다. RAW_TERMINAL과 구분한다.

## 구현 계약

1. 서버 연결에서 검증한 기기·input floor·draft revision을 사용한다. payload의 client.type/id만 믿어 Chat 모드나 사용자를 판정하지 않는다.
2. iPhone 본문+Enter는 draft/첨부 검증 후 Component·병합 Message·receipt를 함께 commit한다.
3. Mac plain/bracketed 본문은 영속 draft에 쌓고 별도 CR에서 submit한다. clear→body→CR ingress 순서와 서로 다른 기기/floor의 격리를 유지한다.
4. 확인된 Chat clear는 draft 편집이며 commit 후 ACK한다. provider에 즉시 보내거나 이미 접수된 Message를 삭제하지 않는다. orphan/만료 draft도 접수 Message 수명과 구분한다.
5. 이미지 paste는 durable 첨부와 최종 Enter를 연결한다. slash/질문 paced key sequence는 별도로 인식하고 완성할 수 없는 형태를 일반 prompt로 조합하지 않는다.
6. ESC는 판별 가능한 Stop 대상만 transaction에서 고정한다. 확정 가능한 중복 gesture는 같은 대상에 결합하며 모호한 늦은 ESC를 새 입력/실행에 replay하지 않는다.
7. query-reply는 wake/Message/업무 활동을 만들지 않는다. raw bytes는 P1-19의 현재 PTY incarnation에만 전달한다.
8. managed Chat 접수 성공은 durable commit 뒤 기존 `send.accepted=true`, `bytesWritten=0`이다. legacy request ID가 제공하는 범위를 넘는 dedup을 주장하지 않는다.

## 완료·검증 기준

V1-04/05에서 iPhone/Mac 동시 입력, Mac clear/body/CR 각 경계 crash, warm→cold 전환, 첨부/slash/질문, 빠른 ESC 두 번+새 입력을 검증한다. 작성자 본문이 섞이지 않고 접수된 Message가 clear로 지워지지 않는다. 타깃 불명 ESC와 준비 전 지원 불가 raw 입력은 기존 실패/불명 계약으로 처리한다.

## 산출물·한계

기기별 분류/draft 계약·wire 결과·실기기 증거를 제출한다. 모든 legacy Stop을 정확히 겨냥할 수 있다는 보장은 하지 않으며 G-02의 확인 범위만 활성화한다.
