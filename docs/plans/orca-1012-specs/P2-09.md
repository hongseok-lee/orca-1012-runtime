# P2-09 — 실제 Claude/Codex Snapshot 통합 qualification

상태: 구현·통합 검증 미착수 · 단계: Phase 2 / 착수 묶음 6.
선행: [P2-01](P2-01.md)~[P2-08](P2-08.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §15–16·§18. [공통 계약](COMMON.md)을 적용한다.

## 목적과 범위

개별 PoC와 구현을 실제 provider·NFS·플랫폼 장애 경계에서 통합 검증한다. Sol 6.1/high worker가 원격 증거를 제출하고 root가 기능별 활성화 범위를 판정한다. 합성 same-node 결과와 실제 결과를 별도로 기록한다.

## 완료 판정

1. 각 행에 실제 소스/image/CLI/runtime/CRD/config/policy revision, 대상 identity와 재현 가능한 증거를 연결한다.
2. memory/gate/입력/NFS/외부 연결의 각각의 보장을 따로 증명한다. Pod Ready나 Snapshot API 성공 하나로 전체를 통과시키지 않는다.
3. 미검증·미지원·실패와 cold fallback 동작을 구분한다. 실패한 memory 경로를 활성화하지 않으며 Phase 1 cold의 안전 계약을 유지한다.
4. 역사적 CPU 직접 복원 성공/RAM 직접 복원 실패/합성 복합 증량 성공을 현재 결과로 재사용하지 않는다. upstream 수정 반영 여부도 실제 버전으로 확인한다.

## 산출물·범위 밖

통합 행렬·실제 provider/fault 증거·기능별 제한과 root 판정을 남긴다. mid-turn FROZEN_TURN은 P2-10의 별도 선택 검증이며 이 작업의 quiescent 성공으로 허용하지 않는다.
