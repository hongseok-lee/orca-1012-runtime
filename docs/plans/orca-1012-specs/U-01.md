# U-01 — cold resume 뒤 미완료 작업 자동 계속의 추가 계약

상태: 사용자 결정 대기 · 구분: 미확정 요구, 구현 지시 아님.
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) 사용자 피드백 항목 3·§8.3·§16, RV-10 (비공개 운영 기록). [공통 계약](COMMON.md)을 적용한다.

## 목적과 현재 범위

정본에서 사용자 입력 대기로 남긴 추가 자동 계속 정책을 추적한다. 별도 파일로 만들었다는 이유로 정책이 결정됐거나 구현 승인이 추가된 것으로 취급하지 않는다.

## 이미 확정된 계약

- cold native-session resume와 동일 Session/Tab/handle binding은 P1-11에서 구현한다.
- 원 입력·receipt·provider history/turn 증거를 대조하고 처리가 확인된 Message를 자동 재전송하지 않는다.
- 외부 효과가 불명확하면 UNKNOWN을 보존한다. 취소된 UNKNOWN의 과거 미완료 작업은 자동 계속하지 않는다.
- 최신 취소/UNKNOWN/실패 context를 다음 정상 입력 전에 전달하며 새 독립 입력을 처리한다. 이력만으로 wake하지 않는다.

## 미확정 부분과 처리

기존 계약에 더해 미완료 작업을 언제·어떤 증거/대상으로 자동 계속할지의 추가 정책은 확정하지 않는다. worker가 원 prompt 재실행, 강제 UNKNOWN 해소, 무조건적인 자동 계속을 기본값으로 선택하지 않는다.

후속 사용자 결정이 오면 root가 원문·결정 내용·영향 작업과 검증 기준을 기록해 P1-08/11 및 필요한 Phase 2 경로의 명세를 갱신한다. 리뷰 의견이나 코드 편의가 그 결정을 대신하지 않는다.

## 종료 조건

사용자 결정의 출처와 적용 범위가 기록되고, 기존 취소/UNKNOWN·receipt 계약과의 충돌 여부를 root가 검토한 뒤에만 결정 완료로 바꾼다. 기능 구현/검증 완료는 별도로 판정한다.

## 비차단 범위

이 추가 정책 대기는 이미 확정된 Phase 1 cold 복구·입력·취소·context 작업 전체를 막지 않는다.
