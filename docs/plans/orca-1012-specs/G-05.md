# G-05 — Claude/Codex 수락·interrupt·native resume·context 실증

상태: 증거 미확보 · 구분: provider 기능 활성화 gate.
연계: [P1-08](P1-08.md)·[P1-09](P1-09.md)·[P1-11](P1-11.md)·[P1-17](P1-17.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §7–8·§12·§16. [공통 계약](COMMON.md)을 적용한다.

## 목적과 범위

두 실제 provider에서 STAGED·수락·완료·interrupt·불명 상태를 구분할 수 있는 계약을 확인한다. 합성 provider나 PTY write 성공을 실제 모델 수락으로 바꾸어 보고하지 않는다.

## 확보할 계약·자료

1. provider/CLI/image revision과 실제 native Session·turn/receipt·readiness 증거의 관계를 기록한다.
2. send 응답 유실·provider 호출 뒤 crash에서 결과를 조회할 수 있는 범위와 UNKNOWN으로 남겨야 하는 구간을 확인한다.
3. 유효한 질문/승인·취소 대상 revision과 interrupt 결과를 확인한다. 취소 요청 접수와 실제 중단 증거를 분리한다.
4. 영속 파일 기반 cold native resume 뒤 동일 Session/Tab/handle에 binding되는 경로를 검증한다. 원래 provider transcript/JSONL을 임의 수정하지 않는다.
5. 취소·UNKNOWN·사건 실패 context가 다음 정상 입력 전에 실제 provider로 전달된 증거를 남긴다. 이력 전달만을 위해 wake하지 않는다.
6. 사용자 지정 최대 허용·permission-skip 설정이 신규 시작과 복구에서 유지되는지 확인한다.

## 완료·검증 기준

- Claude와 Codex 각각 V1-05/06/08에 필요한 실제 ID·receipt·history·interrupt 증거가 있다.
- 처리가 확인된 Message는 자동 재전송하지 않고 불명 Message는 UNKNOWN으로 보존한다. 외부 효과 전체의 exactly-once를 주장하지 않는다.
- UNKNOWN 후 취소한 과거 작업이 자동 계속되지 않으며, 새 독립 입력과 복구 context 전달은 가능하다.
- 확인할 수 없는 adapter capability는 미지원/미검증으로 남기고 공개 지원 판정에 반영한다.

## 산출물

provider별 지원·증거 행렬, 원격 재현 결과와 context 전달 경로를 제출한다. 실제 provider 로그 원문이 필요한 경우 보호된 증거 위치를 참조하고 자격정보를 명세나 일반 로그에 복사하지 않는다.
