# G-04 — 이전 Compute·NFS writer의 실제 차단 검증

상태: 전체 차단 증거 미확보 · 구분: 보호 범위의 writer 교체 전 필수 gate.
연계: [P1-09](P1-09.md)·[P1-10](P1-10.md)·[P1-13](P1-13.md)·[P1-14](P1-14.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §11–12·§16. [공통 계약](COMMON.md)을 적용한다.

## 목적과 범위

제어면과 단절된 옛 실행이 복귀해도 같은 실제 Agent 홈·provider 상태·보호된 checkout에 새 실행과 동시에 쓸 수 없음을 검증한다. DB lease 만료, gateway HTTP 거절, Pod object 삭제는 단독으로 NFS 쓰기 차단 증거가 아니다. 별도 공용 협업 공간의 서로 다른 Agent RW는 [공용 RW 범위 확정](../orca-1012-shared-rw-scope.md)에 따라 허용하며, 그 경로로 보호 범위의 차단을 우회할 수 없음을 검증한다.

## 확보할 계약·자료

1. 대상 attempt·Pod UID·node·execution epoch·storage binding/grant와 실제 디렉터리를 고정해 시험한다.
2. 제어면 단절 후에도 살아 있는 옛 프로세스의 NFS 쓰기 가능성을 관측한다. 재연결·지연 명령·옛 term 복귀 상황을 포함한다.
3. Phase 1 새 RW는 이전 Compute의 실제 종료 증거 뒤에 허용한다. 선택한 차단 방식의 성공·불명·실패를 구분한다.
4. alias/symlink/상하위 중첩 경로를 같은 보호 범위로 검증하며 RO mount의 실제 쓰기 거절도 확인한다.
5. 실패/불명 상태에서는 REVOKING/BLOCKED를 보존하고 새 RW를 열지 않는다. cold resume로 바꾼다고 이 gate를 생략하지 않는다.

## 완료·검증 기준

- V1-09의 단절→차단→새 grant→옛 실행 복귀 순서에서 같은 보호 범위의 중복 활성 RW가 0이다(활성 RW 최대 1).
- 증거의 대상 UID/epoch가 실제 차단 대상과 일치한다. 이름 재사용이나 오래된 종료 결과로 다른 attempt를 허용하지 않는다.
- 명령 수락 뒤 Active 교체와 이전 term 재등장에서도 중복 실행·옛 grant 수락이 없다.
- 차단을 증명하지 못하는 substrate는 미통과로 남고 기능을 활성화하지 않는다.

## 산출물

실제 Compute 종료/차단 증거, storage grant 전이와 쓰기 시도 결과, 실패 시 BLOCKED 유지 결과를 제출한다. 차단 증거의 효력 범위와 관측 한계를 함께 기록한다.
