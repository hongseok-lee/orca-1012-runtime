# P1-27 — 기존 Browser Tab의 모바일·데스크톱 운영 UI

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 4.
선행: [P1-16](P1-16.md)·[P1-26](P1-26.md). 실제 앱 gate: [G-02](G-02.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §13.1–2. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

설치 앱의 기존 Browser Tab으로 중앙 운영 화면을 제공한다. 수정 경계는 서버 제공 반응형 UI·Browser 실행/streaming·기존 인증 연결·영속 Browser Tab 등록이다. iPhone/Mac 앱 자체는 수정하지 않는다.

## 표시·연결 계약

1. 기존 `browser.tabCreate`와 실제 browser-screencast capability를 사용한다. Browser 실행/streaming은 중앙 환경에 두어 Agent Pod/SSH가 없어도 열린다.
2. 영속 Catalog의 기존 tabs list/subscribe에 Browser Tab을 등록한다. 단순 URL 전달만으로 설치 앱 동작을 보장하지 않는다.
3. 모바일은 Agent 카드와 접는 상세, 데스크톱은 자원 표와 사건 타임라인을 제공한다.
4. 별명·논리 Session 상태·실제 Pod/Node/Spot·desired/admitted CPU/RAM·usage/peak·다음 축소 시각·pending 묶음/구성 입력 수·mount 소유권·사건/알림을 구분해 보여준다.
5. 접수와 실제 완료, 현재 request와 다음 request, 읽음과 해결, 마지막 관측과 관측불명을 구분한다. 앱 Active 숫자를 Pod 수로 재사용하지 않는다.
6. Phase 1의 Snapshot 제어는 숨기거나 Phase 2 예정으로 표시한다. 화면 조회·SSE 연결이 Agent의 idle을 늘리거나 wake하지 않는다.
7. 기존 인증을 이어주며 URL/일반 로그에 키를 넣지 않는다. 명령은 P1-26 durable operation을 사용한다.

## 완료·검증 기준

V1-14를 실제 iPhone/Mac에서 수행한다. Agent Pod 0, 기존/새 Browser Tab, 인증 연결, 모바일/데스크톱 배치, command 접수→완료/실패, 로그 reconnect, 읽음/조건 회복을 확인한다. 단순 중앙 HTTP 접근이나 합성 브라우저 성공만으로 설치 앱 합격을 대신하지 않는다.

## 산출물·연계

UI/중앙 Browser 연결 변경과 기기별 재현 결과를 제출한다. 실제 미지원/미검증 capability는 G-02에 기록하고 제품 화면에서 과장하지 않는다.

## 병렬 납품 경계

P1-16 Browser/identity와 P1-26 HTTP/auth/replay 계약을 확정한 뒤 API 담당과 별도 worker가 UI를 작성할 수 있다. fixture로 수행한 화면 검증은 실제 backend command·기존 Browser Tab·설치 앱 합격과 구분한다. 기능별 실제 서버 연결 후 Expo iPhone 화면 클릭과 스크린샷을 PR에 남기며, G-02의 설치 앱 검증 조건은 계속 추적한다.
