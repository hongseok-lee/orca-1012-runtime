# P1-11 — Claude/Codex provider adapter·cold native resume

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 2.
선행: [P1-08](P1-08.md)·[P1-09](P1-09.md)·[P1-10](P1-10.md). 완료 gate: [G-05](G-05.md).
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §7–8·§10.5·§12. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

영속 파일과 provider-native session을 사용해 새 attempt를 기존 논리 Session/Tab/handle에 연결한다. 수정 경계는 provider 시작/resume·readiness·admission·interrupt·context adapter와 binding이다.

## 구현 계약

1. 현재 영속 디렉터리와 실제 native session identity로 명시적 cold 실행을 선택한다. Snapshot이 자동 선택되지 않게 한다.
2. 이전 writer 차단과 새 실행 소유권을 확인한 뒤 provider를 시작하고 실제 readiness/handle을 기존 논리 객체에 bind한다. 가짜 provider ID를 생성하지 않는다.
3. stage·provider 수락·완료·interrupt를 별도 증거로 기록한다. PTY write만 성공한 요청을 ADMITTED로 표시하지 않는다.
4. 최신 질문·취소·context revision을 대조하고 다음 정상 입력 전에 필요한 context를 전달한다. native transcript/JSONL을 플랫폼 상태 기록으로 변조하지 않는다.
5. receipt/history 등으로 처리가 확인된 Message는 자동 재전송하지 않는다. 외부 효과가 불명확하면 UNKNOWN을 보존한다.
6. 취소된 UNKNOWN의 과거 미완료 자동 계속을 금지하고 새 독립 입력을 진행한다. 추가 계속 정책은 U-01에 남긴다.
7. 사용자 지정 최대 허용·permission-skip 설정을 신규 시작·복구 모두 유지한다.

## 완료·검증 기준

- V1-06/08을 실제 Claude와 Codex에서 각각 수행한다. Spot/crash cold 복구 뒤 동일 Session/Tab/handle과 기존 기록이 유지된다.
- provider 호출 직후 crash·응답 유실·interrupt 실패에서 증거에 맞는 상태가 남는다.
- 처리가 확인된 Message 자동 재전송은 0이고, 불명 상태를 임의 미실행으로 바꾸지 않는다.
- 실제 context 전달이 다음 정상 입력보다 앞서며 닫힌 Tab/취소 대상이 복구로 부활하지 않는다.
- 합성 provider 결과와 실제 provider 결과를 분리해 G-05 행렬을 갱신한다.

## 산출물

provider별 adapter/binding 계약·원격 실행 결과·receipt/context/native resume 증거를 제출한다. NFS 파일 백업 성공을 native resume 합격 증거로 대신 사용하지 않는다.

## 병렬 납품 경계

- root가 P1-08 context·P1-09 Port·P1-10 writer 및 공통 provider 결과 계약을 확정한 뒤 Claude와 Codex adapter를 두 worker에 나눈다. 실제 파일 분리와 공통 binding/type 반영 소유자를 먼저 지정한다.
- 같은 P1-11에 연결된 provider별 PR·G-05 증거를 제출한다. 공통 변경을 서로 복제하지 않고 provider별 실제 receipt/interrupt/context/cold 결과를 구분한다.
- 작성 중에는 확정된 계약 부분만 사용할 수 있다. 실제 실행은 선행 모듈·writer 차단·원격 환경과 합류하며, 두 provider와 공통 경합 검증이 모두 충족돼야 P1-11을 완료한다.
