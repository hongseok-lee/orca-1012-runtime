# P1-29 — 검증된 대체 경로의 옛 restart·idle·outbox 제거

상태: 구현 미착수 · 단계: Phase 1 / 착수 묶음 4, 대응 기능별 점진 적용.
선행: 제거 대상마다 대응 신경로의 실제 검증 통과.
근거: [1012 정본](../../reference/haagent-20261012/plans/orca-durable-session-snapshot-rpc-spec-20261010.md) §2·§14. [공통 계약](COMMON.md)을 적용한다.

## 목적과 수정 경계

새 PG 정본과 경쟁하는 옛 상태/제어 경로를 제거한다. 수정 경계는 G-01에서 확인한 기존 메모리 Map/JSON outbox 특례, 화면별 SSH 상태 판정, 중복 restart·idle·resource loop와 호출부다.

## 제거 계약

1. 각 구경로에 대응하는 새 작업 ID·수정 파일·검증 증거를 연결한 뒤 root가 제거 범위를 지정한다. 전체 구코드를 한 번에 정리하는 작업으로 확대하지 않는다.
2. 대체 기능의 수락/복구/조회가 실제로 검증되기 전 기존 동작 경로를 제거하지 않는다. 제거 후 제어 소유자와 durable 정본이 하나로 수렴해야 한다.
3. 기존 iPhone/Mac wire와 필요한 legacy adapter는 유지한다. legacy 입력 지원과 옛 휘발성 outbox 구현을 혼동하지 않는다.
4. 새 dataset epoch로 시작하며 과거 JSON/개발 데이터 이관기를 만들지 않는다. 삭제 범위는 지정된 Orca 개발 데이터에 한정한다.
5. 계정 자격·공유 인프라·백업·다른 프로젝트·동결 템플릿과 이력은 제거 대상이 아니다. 과거 기록 문서는 이력으로 보존한다.

## 완료·검증 기준

- 제거 전 대응 신경로의 revision·원격 합격 증거가 존재한다.
- 제거 후 해당 RPC/복구/idle 경계의 의미 있는 회귀 검증을 통과한다. 이미 통과한 무관한 시험 전체를 이유 없이 반복하지 않는다.
- 같은 상태를 바꾸는 경쟁 loop·새/옛 outbox 이중 소비·SSH/PG 혼합 projection이 남지 않는다.
- 실제 변경/삭제 파일과 데이터 범위가 root 지정 범위와 일치하며 보호 대상은 보존된다.

## 산출물·연계

구경로→대체 작업→증거 대응표, 제거 diff와 필요한 회귀 결과를 제출한다. P1-30은 이 결과를 포함해 Phase 1 전체를 판정한다.
