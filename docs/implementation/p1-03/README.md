# P1-03 actual atomic storage and publication module

New actual exports: db/atomic.ts runDurableMutation/resolveReceipt; journal/store.ts appendSessionEvent/enqueueOutbox/appendAudit; journal/publisher.ts claimOutbox/markOutboxPublished/recordOutboxFailure/publishOutboxClaim. Existing DurableTransaction signatures remain; isLockHeld/markLockAcquired are additive. SQL-success-held tracking permits same-row reentry, preserves initial rank/key order and rejects a newly acquired reverse Session. Journal uses that same Session lock path.

Mutation data changes and receipt, explicitly called journal/outbox/audit helpers share one transaction. No hidden callback COMMIT/batch/session override, no automatic callback retry. Receipt is rechecked after aggregate locking; uniqueness conflict rolls back then reads the same key. Authentication/ownership including replay is the upper domain's responsibility. The SQL callback guard is a trusted-module transaction boundary, not an untrusted SQL sandbox.

COMMIT connection failure returns UNCERTAIN with original key/hash. resolveReceipt returns FOUND/NOT_FOUND/UNAVAILABLE without inventing new effects; NOT_FOUND is point-in-time, not proof to create a new key. Uncertain/failed-rollback clients are destroyed. Active/idle client errors are sanitized; no raw URL/credential errors are logged.

Source identity uses Session+source kind+native provider/lineage/id or producer/incarnation/seq, never body hash or snapshot local seq alone. Session journal allocation/insert share the lock; epoch is not changed by this module. Outbox original event is immutable. Bounded claims commit before callback I/O; expired claims can be taken over. Publication failure retains attempt/error and retryable row. Same canonical ID may be delivered after publication but before completion marker: at-least-once subscriber dedup, not exactly-once or global replay commit ordering.

Audit stores typed actor/device/unit/Session/operation/attempt/Pod/node/profile/ref and timestamp fields with an empty body payload. Callers provide safe state/evidence references; this module does not copy request/credentials into ordinary logs. recordedAt is the transactional DB INSERT timestamp, not measured WAL flush time. commitObservedAt follows commit confirmation in worker wall clock; transactionDurationMs is monotonic. They are distinct clocks, not app E2E measurements.
